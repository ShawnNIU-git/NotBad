# NotBad 路线图

面向中小学生的 iOS 错题本：拍试卷 → 自动识别错题 → 存入错题本 → 复习。个人开发。

## 核心链路与风险

拍照 → 图像矫正 → 切题 → 识别（含公式、图形）→ 判断对错 → 入库 → 复习

"判断对错"风险最高，分三档逐步实现：

1. **学生手动框选错题**：软件只做裁剪、识别、归档。MVP 先做这一档。
2. **识别老师批改痕迹**：红叉、扣分。有批改的卷子可行，靠视觉模型。
3. **AI 自己判题**：需要标准答案和手写识别，准确率最难保证。

## 阶段

| 阶段 | 内容 | 状态 |
|---|---|---|
| 1. 需求验证 | 访谈 5–10 位家长或老师：现在怎么整理错题，痛点在哪 | 待做 |
| 2. 识别原型 | 电脑上用视觉模型跑通"切题 + 判错"，用 100–200 张标注照片做评测集 | **进行中**，见 [`recognition/`](../recognition/README.md) |
| 3. 手动版 MVP | SwiftUI + VisionKit 扫描 + 手动框选 + Vision OCR + 标签 + 复习列表 | 待做（需要 Mac） |
| 4. 加入自动化 | 自动切题 → 批改痕迹识别 → AI 判题，每步用评测集量化 | 待做 |
| 5. 周边功能 | 账号、同步、家长端、PDF 导出、订阅付费 | 待做 |
| 6. 合规与上架 | 隐私政策、监护人同意、App 备案、App Store 审核材料 | 贯穿始终 |

阶段 2 的通过标准（建议）：在评测集上，有批改痕迹的卷子错题召回率 ≥ 90%，切题召回率 ≥ 90%。达不到就先只上线手动框选，自动识别作为"建议"展示。

## iOS 技术选型

- **界面**：Swift + SwiftUI，最低支持 iOS 17（可用 SwiftData）。
- **扫描矫正**：VisionKit `VNDocumentCameraViewController`，自带边缘检测和透视校正。
- **本地 OCR**：Vision `VNRecognizeTextRequest`，支持简体中文，离线免费；公式和手写较弱。
- **云端识别**：视觉大模型做切题、转 LaTeX、识别批改痕迹。API key 不能放客户端，经自己的服务器中转（可用 Cloudflare Workers 等轻量方案），顺便做限流和成本控制。
- **存储**：SwiftData 存元数据，图片存文件系统。
- **同步**：先用 CloudKit；要做家长端或跨平台再自建后端。
- **公式显示**：SwiftMath，或 KaTeX + WKWebView。

## 数据模型草案（MVP）

```
Paper     试卷：id, 拍摄时间, 学科, 原图路径, 备注
Mistake   错题：id, paperId, 题号, 裁剪图路径, 题干文字(LaTeX), 学生答案, 正确答案,
                错因标签[], 知识点[], 来源(手动/批改痕迹/AI), 置信度, 创建时间
Review    复习记录：id, mistakeId, 时间, 结果(会/不会/模糊)
Schedule  复习计划：mistakeId, 下次复习时间, 间隔, 难度系数（间隔重复，如 SM-2）
```

识别原型输出的 JSON（`recognition/notbad_recog/schema.py`）字段与 `Mistake` 对应，后端中转时可直接复用同一份提示词和格式。

## 必须提前考虑的问题

**产品**
- 付费方通常是家长：PDF 打印错题、举一反三推荐相似题。
- 先聚焦一个学科、一个学段（建议初中数学：需求最强，难度也最高）。
- 核心价值在复习闭环：间隔重复、错因标签、知识点归类。
- 差异点要想清楚（对比作业帮、小猿等）：切题体验、复习闭环、隐私友好。

**工程**
- 真实拍摄质量差：阴影、折痕、手指遮挡、倾斜。
- 切题难点：题号识别、跨栏、跨页、带图题。
- AI 不会 100% 准确，手动修正界面必须好用。
- 云端识别按次计费，算清单用户成本和免费额度。

**合规（面向未成年人，不能后补）**
- 不满 14 周岁的个人信息属于敏感个人信息，需监护人单独同意。
- 遵守《未成年人网络保护条例》（2024 年 1 月 1 日施行）。
- 试卷照片含姓名、学校、班级：本地脱敏，最小化上传（只传裁剪后的题目区域）。
- 选择不用用户数据训练的模型服务，并写进隐私政策。
- 国内上架需要 App 备案；用到生成式 AI 还要关注相关备案要求。
- 将来做共享题库要先处理试卷版权。
